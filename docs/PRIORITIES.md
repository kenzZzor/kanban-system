# Приоритеты и очередь этапов

Один этап = одна сессия агента = один вертикальный срез = один коммит.
Оценка ориентировочная (по состоянию кода на момент ревью).

## 1. Обязательно (без этого релиз нельзя считать рабочим)

Фундамент
- Единый формат ошибок и обёртка `apiHandler` (убрать дублирование 401/403/try-catch).
- Мутация + запись в Activity в одной `prisma.$transaction` (участники, департаменты, далее все).
- Миграция `ActivityLog`: `departmentId` (+индекс), `taskId` без каскадного удаления, новые типы событий.
- `getSession`/`getCurrentUser`: не тянуть `passwordHash`, проверять `isActive`.
- Логин: Zod-валидация, неожиданные ошибки = 500, а не 400.
- Скрипты `typecheck`, `test`, `db:migrate`, `db:seed`; рабочий prisma config.
- Тесты на `POST /api/departments/:id/members`.

Организация
- Смена роли и руководителя: проверка циклов, менеджер = активный участник того же департамента.
- Защита последнего `DEPARTMENT_ADMIN`; защита от эскалации ролей.
- Мягкое удаление участника (`leftAt`).

Задачи
- Политика `can(user, action, task)` для задач с двумя департаментами.
- Поля `Task.position` и `Task.version` (409 при конфликте).
- Исполнитель обязан быть участником `assignedDepartment`.
- Статусы: таблица + карта переходов в коде (глобально).

UI и безопасность (минимум)
- Логин, оболочка со sidebar, департаменты, участники, список задач, Task Details, Kanban.
- Rate limit на логин; проверка `Origin` на мутациях (CSRF); защита seed от production.
- Backup БД + проверенный restore; health endpoint.

## 2. Позже (после работающего MVP)

- Одинаковое время ответа логина при несуществующем email.
- Ограничение записи `lastUsedAt` (раз в 5 минут).
- Fractional indexing вместо простого `position`.
- Рекурсивная видимость задач по иерархии (оптимизация).
- Кэш прав на запрос; Vitest + изолированная тестовая БД.
- Reports, Settings (расширенные), Profile/активные сессии.
- Вложения, чек-листы, теги.
- Уведомления о приближении дедлайна.
- Nginx + HTTPS, расширенное логирование.
- Переход с bcryptjs на нативный bcrypt/argon2.

## 3. Необязательно

- Модель Teams (дублирует департамент и иерархию).
- Per-project/per-department workflow.
- Saved views, массовые действия, глобальный поиск.
- Реалтайм (SSE/WebSocket), виртуализация списков.
- i18n, SSO, внешние интеграции.
- Очистка `.gitignore` (косметика).
- Решить судьбу `Department.managerId` (дублирует иерархию); пока не использовать.
