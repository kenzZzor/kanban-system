# Инструкция для агента (читать перед каждой задачей)

Проект: корпоративная Kanban-система. Next.js 16, TypeScript strict, Prisma 7,
PostgreSQL, Zod, Playwright. Modular monolith. Подробности: AGENTS.md,
docs/PRIORITIES.md.

## Текущее состояние
Готово:
- auth (серверные сессии), RBAC (hasPermission, права ролей из БД);
- единый API-слой: lib/api/errors.ts, lib/api/handler.ts (apiHandler, requireUser),
  формат ошибок { error: { code, message, details? } };
- GET/POST departments, GET/POST members, GET users;
- activity log (logActivity с необязательным tx), seed, тесты API;
- скрипты: typecheck, lint, test, test:unit, db:migrate, db:seed, db:generate.

Нет: UI, API проектов и задач (модели в schema.prisma есть), управление
участниками (роль, руководитель, удаление), уведомления.

## Правила работы (экономия токенов)
1. Читай ТОЛЬКО файлы, названные в задаче. Не сканируй репозиторий.
2. Сначала план: список файлов и шагов. Код не пиши, пока не получишь "ок".
3. Правки точечные. Не переписывай файлы целиком, не создавай дубликаты.
4. Не менять schema.prisma, зависимости, структуру папок без явного
   разрешения в тексте задачи.
5. Без mock-данных. Права проверяются на сервере. Вход валидируется Zod.
   Не доверять departmentId, userId, roleId, managerId из клиента без проверки.
6. Все новые роуты оборачивать в apiHandler и бросать AppError-подклассы.
   Формат ошибок единый, ничего своего не изобретать.
7. Мутация + запись в Activity в одной prisma.$transaction
   (logActivity принимает tx).
8. Проверки только указанные в задаче. Полный набор тестов не запускать,
   если задача не требует.
9. При ошибке максимум 2 попытки исправления, затем остановись и опиши проблему.
10. Не делай то, чего нет в задаче (рефакторинг "заодно", новые фичи,
    обновление версий пакетов).
11. Не делать git commit, git push, git reset и любые команды git, меняющие
    историю. Коммитит человек после проверки.
12. Не запускать db reset и prisma migrate reset без явного разрешения.
13. Финальный ответ: изменённые файлы, новые env и миграции, что проверить
    вручную. Без пересказа кода.

## Формат задач
Каждая задача приходит с разделами: файлы для чтения, требования, ограничения,
проверки. Если в задаче чего-то не хватает или есть противоречие с этими
правилами, остановись и задай один вопрос до начала работы.
