# Состояние проекта

> Этот документ описывает только фактическое состояние реализации. Полный целевой план и бизнес-требования находятся в [`DEVELOPMENT_PLAN.md`](DEVELOPMENT_PLAN.md).

## Подтверждённое состояние backend

Последний подтверждённый функциональный коммит кода: `71b8cd1 feat: complete department members API`. Последующий коммит `6e9b808` содержит только реорганизацию документации, без изменений прикладного кода.

### Инфраструктура и данные

- Next.js 16, TypeScript strict, PostgreSQL, Prisma 7 и локальный Podman/Compose workflow.
- Prisma schema, миграции, генерация клиента и development seed.
- В Prisma есть базовые модели пользователей, сессий, ролей, permissions, подразделений, членств, проектов, задач, комментариев, Activity и уведомлений.
- Наличие моделей проекта/задачи/комментария/уведомления не означает, что их полноценные API и UI реализованы.

### Аутентификация и доступ

- Session-based authentication: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`.
- RBAC и серверная проверка permissions.
- `SYSTEM_ADMIN` — глобальная роль; `DEPARTMENT_ADMIN`, `MANAGER`, `EMPLOYEE`, `VIEWER` — роли членства в подразделении.
- Общий API error handler доступен для маршрутов, переведённых на него; старые маршруты ещё могут использовать собственные контракты. Не утверждать, что все ошибки уже имеют единый формат.

### Организация

- `GET/POST /api/departments`.
- `GET /api/users`.
- `GET/POST /api/departments/:departmentId/members`.
- `PATCH/DELETE /api/departments/:departmentId/members/:memberId`.
- Реализованы правила активного пользователя, добавления/реактивации, роли, назначения руководителя, проверки членства руководителя в том же подразделении, циклов и недопустимой иерархии.
- Запрещено удаление последнего активного `DEPARTMENT_ADMIN` и участника с активными подчинёнными, пока не исправлена иерархия.
- Используется мягкое прекращение членства через `leftAt` и Activity logging для соответствующих операций.

## Последняя подтверждённая проверка

Для среза Department Members API ранее успешно прошли:

- `npx tsc --noEmit`;
- `npm run lint`;
- `npm run test:unit`;
- целевые Playwright suites для members — 28 тестов;
- `npm run build`;
- `git diff --check`.

Эти результаты относятся к тому срезу и не гарантируют успешность последующих изменений. После новых правок нужные проверки должны быть запущены заново.

## Не реализовано как законченный функционал

- Frontend: login UI, защищённая оболочка, sidebar, страницы подразделений и участников.
- Полноценные Project API и UI.
- Task API: создание, чтение, изменение, архивирование, права на задачу, назначения, workflow и конкурентные обновления.
- Целевой пятиэтапный Kanban workflow с проверкой постановщиком пока не реализован и требует утверждения точной семантики.
- История длительности статусов и таймер выполнения задач.
- Массовое назначение одной и той же работы нескольким сотрудникам с независимым прогрессом.
- Междепартаментное прямое назначение и workflow запроса/принятия.
- API/UI комментариев, пользовательская лента Activity и уведомления.
- Kanban board, drag-and-drop и аналитический dashboard, включая сводный экран VIEWER.
- Учёт рабочего времени, ежедневные отметки начала/завершения, расчёт 8-часовой нормы с часовым обедом и уведомления менеджеру.
- Admin/audit UI, login rate limit, Origin/CSRF checks, production seed guard, health endpoint и backup/restore process.
- Финальная унификация отображения пользовательских ошибок в UI.
